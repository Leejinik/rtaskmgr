# MK119 v10 리소스 수집 등록

사이드바의 **MK119 리소스 수집 등록**에서 사용합니다.

1. MariaDB(`liz` 스키마), Redis, Kafka 연결 정보를 입력합니다. 기본 포트는 3306 / 5000 / 9092이며 계정·비밀번호·주소·포트는 수정할 수 있습니다. Redis ACL 계정은 선택 사항입니다. Kafka는 PLAINTEXT, SSL, SASL/PLAIN을 지원합니다.
2. 연결을 확인하고 Redis의 `liz.stats.*` 키를 조회합니다. `KEYS` 명령 대신 `SCAN`을 사용합니다.

**Kafka 서버**에 호스트 이름 · IP · 포트를 입력하고, **+ 서버 추가**로 필요한 대수만큼 행을 추가합니다. 호스트 이름은 Kafka advertised listener의 이름 그대로 입력합니다(예: `server_1`, `server03`). 각 행은 초기 접속 주소와 앱 내부 호스트 바인딩에 함께 사용됩니다. 연결 확인·알림 전송·재시도에 동일하게 적용되며, OS hosts 파일은 수정하지 않습니다. 매핑하지 않은 이름은 기존 DNS/hosts로 해석합니다. TLS 인증서 검증은 원래 호스트 이름을 유지합니다.

3. 그룹 이름(기본 `System`), 장비 탐색기, Collector 클러스터, 서버별 Device 이름을 확인합니다. Device 이름 기본값은 실제 hostname이며 수정할 수 있습니다. RHEL 버전별 이름 생성은 사용하지 않습니다.
4. 모듈 ID가 포함된 키는 `liz_module`의 hostname으로, 호스트 식별자가 포함된 키는 해당 서버로 배치합니다. 식별자가 없는 공통 키는 `common`에 배치합니다. 알 수 없는 별칭/모듈 ID는 자동 선택하지 않습니다. 같은 식별자의 키들을 일괄 배치하거나 제외할 수 있습니다.
5. 키별 이름, 수집 주기, 포함 여부를 확인합니다. 드라이버 템플릿이 있는 키는 변환식·자료형·상태 라벨을 재사용합니다. 없는 키는 직접 Redis 키로 등록하며 숫자/문자열 자료형을 확인할 수 있습니다.
6. **등록 전 검사**(입력값·탐색기·Collector 클러스터) 후 등록합니다. 그룹·장비 **이름 중복은 검사하지 않습니다**(2026-09-22 제거 — 같은 이름이 있어도 저장). 중복 차단은 **이미 등록된 Redis 키**에만 적용합니다. 선택한 체크포인트가 있는 장비만 생성합니다.

모든 장비는 ETC / MK119 System / MK119 Cache / MK119 v10 System Stats로 등록됩니다. 카탈로그 ID는 현재 DB에서 조회하며 고정 ID를 사용하지 않습니다.

## 저장 및 실패 처리

- DB의 그룹·소속 규칙·장비·인터페이스·체크포인트·상태 라벨·감사 이력을 한 트랜잭션으로 저장합니다. 웹 API 로그인 없이 MariaDB 및 Kafka 연결로 수행합니다. 웹의 `liz_log` 사용자 작업 로그는 별도로 작성하지 않습니다.
- DB 저장 후 `liz.message.pipeline`에 그룹 갱신, 장비 추가, 체크포인트 갱신, 규칙 갱신 알림을 순서대로 전송합니다. 기존 Kafka 소비자 그룹/오프셋은 변경하지 않습니다.
- Kafka 실패 시 DB 등록을 다시 실행하지 않습니다. 결과 화면의 **알림 재시도**를 사용합니다.
- 복구 기록은 `~/.rtaskmgr/stats-registration/<복구 ID>.json`에 저장됩니다. 앱을 재시작한 경우 연결 화면의 **이전 등록의 Kafka 알림 재시도**에 복구 ID와 원래 연결 정보를 입력합니다. 비밀번호는 이 파일에 저장하지 않습니다.
- 알림 ACK 유실이나 종료 시 동일 UUID 알림이 재전송될 수 있습니다(at-least-once). DB와 Kafka의 분산 원자적 커밋을 보장하는 기능은 아닙니다. 커밋 결과가 불확실하면 DB 존재 확인 후 알림을 재시도합니다.
- 여러 Galera 노드/다른 애플리케이션이 같은 이름을 동시에 삽입하는 상황까지 보장하는 전역 유일 제약은 추가하지 않습니다. 연결한 노드에서는 저장 직전 잠금 검사로 중복을 방지합니다.

## 검증

- `go test ./...`
- `npm run build` (`frontend` 디렉터리)
- `wails build` (저장소 루트)
- 테스트 환경 전용 롤백 통합검증: `RTM_STATS_TEST_HOST`, `RTM_STATS_TEST_PASSWORD`를 설정하고 `go test ./internal/statsreg -run TestLiveRegistrationRollback -v -count=1`.
  이 검증은 실제 스키마에 INSERT/감사 기록을 실행한 뒤 전부 ROLLBACK하며 Kafka 알림을 보내지 않습니다. AUTO_INCREMENT 값에 빈 구간은 남을 수 있습니다.

이번 검증에서는 Redis 100개 키 발견, 서버/common 2개 장비와 76개 체크포인트 및 라벨·감사 이력 삽입/롤백을 확인했습니다. 실제 커밋 후 수집 시작 및 Kafka 알림 전달은 사용자가 최종 이름/배치를 확인하고 등록할 때 확인할 항목입니다.
