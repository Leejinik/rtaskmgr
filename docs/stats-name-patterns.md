# MK119 리소스 수집 등록 — 이름 패턴과 변경 이력

리소스 수집 등록 화면은 **등록에 성공할 때마다** 키별로 사용자가 정한 이름·자료형·주기·선택 여부를 기억한다. 다음 조회 때는 어느 환경이든 같은 모양의 키에 그 값을 채워 넣는다. 채워진 값은 화면에서 고칠 수 있고, 고친 값은 다음 등록 성공 때 다시 기억된다.

- 저장 위치: `~/.rtaskmgr/stats-patterns.json` (PC별 로컬 파일, 저장소에 넣지 않음)
- 코드: `internal/statsreg/patterns.go`
- 이 문서: 규칙 설명과 **규칙이 바뀐 이력**. 규칙이나 이름 정규식이 바뀌면 아래 「변경 이력」에 한 줄 추가한다.

## 키 모양

키의 `{…}` 부분을 모두 `{*}`로 바꾼 것이 키 모양이다. 같은 모양이면 같은 규칙을 쓴다.

| Redis 키 | 키 모양 |
|---|---|
| `liz.stats.cachedb.{server01}.cpu` | `liz.stats.cachedb.{*}.cpu` |
| `liz.stats.server.{server01}.{eth0}.network.traffic` | `liz.stats.server.{*}.{*}.network.traffic` |
| `liz.stats.pipeline.lag` | `liz.stats.pipeline.lag` |

## 이름 템플릿 치환자

이름은 장비(호스트)마다 다르게 채워지도록 템플릿으로 기억한다.

| 치환자 | 뜻 | 예 (hostname `server01`) |
|---|---|---|
| `{Host}` | hostname, 첫 글자만 대문자 | `Server01` |
| `{host}` | hostname 그대로 | `server01` |
| `{n}` | hostname 끝의 숫자 | `server01` → `1`, `server_3` → `3` |
| `{t1}`, `{t2}` … | 키의 첫 번째·두 번째 `{…}` 값 | `…{server01}.{eth0}…` → `{t2}` = `eth0` |

기억할 때는 입력한 이름에서 위 값을 찾아 치환자로 바꾼다. `{Host}` → `{host}` → `{tN}` → `{n}` 순서다. `{n}`은 이름 안에서 **앞뒤가 숫자가 아닌** 첫 번째 해당 숫자 하나만 바꾼다. 채울 때 치환자를 채울 수 없으면(예: `{n}`인데 hostname이 `ELON`) 이름은 기본값으로 둔다.

## 기억하는 것과 규칙

- **이름**: 같은 모양의 키를 여러 장비에 등록했는데 템플릿이 서로 다르면 **다수 쪽**을 채택하고, 다른 이름은 변경 이력의 notes에 남긴다.
- **자료형**: 드라이버 템플릿이 없는 키(직접 키 등록)만 기억한다. 템플릿이 있는 키의 자료형은 바꾸지 않는다.
- **주기**: 기억한다.
- **선택 여부**: 배치된 키를 선택 해제하고 등록했으면 「선택 안 함」으로 기억한다.
- **서버 배치**: 자동으로 서버를 못 찾아 직접 배치한 식별자(예: `{lizlogdb01}` → `server01`)를 기억한다. 조회한 환경에 그 hostname이 있을 때만 적용한다.

## 중복 등록 방지 (패턴과 별개)

- 조회할 때 DB에 **이미 살아 있는(flag=1) 체크포인트로 등록된 키는 목록에서 숨긴다.** 등록 직전에 트랜잭션 안에서 한 번 더 확인하고, 있으면 등록을 거부한다.
- 등록했다가 **삭제된(flag≠1) 키**는 일반 새 키와 똑같이 다룬다(선택 여부는 기본값/기억된 패턴대로). 「이전에 삭제됨」은 참고 표시일 뿐이다.
- 기존 등록이 있는 환경이면 「기존에 등록된 작업을 업데이트하겠습니까?」를 묻는다. 「예」를 누르면 새 키만 받는다. 기존 서버의 새 키는 그 서버의 기존 장비에 넣고, 새 서버는 같은 그룹에 새 장비를 만든다. 원본 키가 사라진 기존 체크포인트는 그대로 둔다.
